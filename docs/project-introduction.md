## 一、项目概述

### 项目名称

公众号文字稿一键排版助手

### 项目简介

这是一个面向微信公众号小编、学生社团运营者和自媒体新手的排版工具。用户把已经写好的文字稿（`.txt` / `.md`）交给它，它自动识别标题、小节、引用、列表和重点句，套用内置风格模板，生成一个**可以直接粘贴进微信公众号编辑器的单文件 HTML**，并在生成后自动检查排版质量。

项目以 **Agent Skill** 的形式交付：`SKILL.md` 告诉 AI 什么时候该用、按什么步骤用；核心功能由可独立运行的 Python 脚本完成，不依赖任何第三方库，也不需要 API Key。

### 项目核心价值

1. **降低排版门槛**：不需要学秀米、135 编辑器，也不需要懂设计，一条命令出成品。
2. **解决"粘贴后样式丢失"**：所有样式写成内联 `style`，不依赖 class、外部 CSS 和脚本。
3. **把审美变成可检查的指标**：对比度、字号、行高、外链、容器宽度等 7 项自动检查，不合格直接报错。
4. **结果稳定可复现**：同样的文字稿、风格和参数，每次输出一致，不依赖大模型临场发挥。

## 二、项目背景

### 实际应用场景

项目作者是一名化工专业学生，日常需要为学生组织和公众号撰写推文。真实的工作流程是：

1. 花一两个小时把文字内容写完；
2. 再花一两个小时调字体、字号、行高、颜色、引用框；
3. 粘贴进公众号编辑器后发现样式丢了，只能重新调；
4. 下次写文章，上面三步再来一遍。

### 现有问题

- **设计工具学习成本高**：秀米、135 等编辑器功能多，新手很难判断"怎样算好看"。
- **模板工具输出固定**：很多模板只能套固定版式，文章结构一变就不适用。
- **AI 直接生成 HTML 不稳定**：普通对话生成的 HTML 常带外部 CSS、class、脚本或外链图片，粘贴进公众号后样式失效；每次生成的结果也不一致。
- **缺少质量底线**：颜色太浅、字号太小、行高太挤等问题，肉眼不一定能及时发现。

### 项目要解决的痛点

把"排版"从一件需要审美和经验的手工活，变成一条**输入文字稿、输出可粘贴成品**的确定性流程，并且用自动检查守住基本的可读性底线。

## 三、技术架构

### 使用的技术

| 层次 | 技术 | 作用 |
|---|---|---|
| Skill 层 | Agent Skills（`SKILL.md`） | 描述触发条件、输入格式、执行步骤和限制 |
| 解析层 | Python 标准库（`re`、`html`） | 把文字稿解析成标题 + 结构化块 |
| 风格层 | JSON 配置（`styles/*.json`） | 保存四套风格的色板、字体、字号、间距 |
| 渲染层 | Python 字符串模板 | 生成全部内联样式的单文件 HTML |
| 校验层 | `html.parser` + WCAG 对比度算法 | 7 项排版质量检查 |
| 测试层 | `unittest` | 17 个自动化测试，覆盖生成、校验和命令行 |
| 演示层 | Playwright（仅截图验证用） | 浏览器实际渲染截图，确认视觉效果 |

### Skill 的作用

Skill 不负责"画页面"，它负责三件事：

1. **判断何时触发**：用户说"公众号排版""文字稿排版""这篇文章太丑了"等时加载。
2. **约束执行流程**：先确认输入，再选风格，再运行脚本，最后必须跑校验。
3. **约束输出质量**：明确 677px 容器、16px 正文、行高 ≥1.6、无外链等要求。

真正的排版计算全部由脚本完成，避免 AI 每次自由发挥。

### 核心执行流程

```text
用户文字稿 (.md / .txt)
        │
        ▼
parse_article()  ── 解析标题、小节、引用、列表、代码块、重点句
        │
        ▼
render_html()   ── 读取 styles/*.json，生成全部内联样式的 HTML
        │
        ▼
validate.py     ── 7 项自动检查
        │            ├─ 禁用标签（script/style/link/iframe）
        │            ├─ 容器宽度 677px
        │            ├─ h1 数量
        │            ├─ 外链资源
        │            ├─ 内联样式覆盖
        │            ├─ 文字对比度（WCAG AA）
        │            └─ 正文字号 14–20px、行高 ≥1.6
        ▼
浏览器预览 → 全选复制 → 粘贴进公众号编辑器
```

### 主要功能模块

| 文件 | 职责 |
|---|---|
| `skill/wechat-article-typesetter/SKILL.md` | Skill 说明书：触发词、输入格式、执行步骤、异常处理 |
| `scripts/typeset.py` | 解析文字稿、加载风格、渲染 HTML、命令行入口 |
| `scripts/validate.py` | HTML 结构解析、对比度计算、7 项检查、JSON 报告 |
| `styles/datawhale.json` | 科技蓝分享会风 |
| `styles/heytea.json` | 杨梅晚熟风 |
| `styles/minimal.json` | 极简书卷风 |
| `styles/academic.json` | 学术理工风 |
| `tests/test_typesetter.py` | 17 个自动化测试 |
| `examples/sample-article.md` | 演示用文字稿 |
| `examples/output/*.html` | 四套风格的实际生成结果 |

### 输入输出关系

| 项目 | 内容 |
|---|---|
| 输入 | UTF-8 编码的 `.txt` / `.md` 文字稿；可选标题、作者、日期、点缀色、风格 |
| 输出 | 单文件 HTML（内联样式、无 JS、无外链、无外部字体） |
| 输出尺寸 | 容器 `max-width: 677px`，正文 16px |
| 使用方式 | 浏览器打开 → 全选复制 → 粘贴进公众号编辑器 |

## 四、核心功能

### 1. 文字稿结构解析

支持标题、小节、次级标题、引用、无序列表、有序列表、代码块、分隔线、加粗、关键词高亮、行内代码。单换行保留为段内换行，空行分段。

### 2. 四套内置风格

| 风格 | 视觉特征 | 适合内容 |
|---|---|---|
| 科技蓝分享会风 | 手机卡片外框、浅灰白底、蓝色英文小标签、黑色大字块导语、空心数字编号、粗黑描边卡片、黄色虚线分隔 | 活动宣传、分享会、招募 |
| 杨梅晚熟风 | 手机卡片式外框、米白纸底、细黑体大字距标题、杨梅红点缀、水彩圆环与圆坑材质图案层、手画圆圈编号、手撕便签引用卡、装订竖线与打孔圆 | 生活、品牌、活动、系列内容 |
| 极简书卷风 | 宋体标题、首行缩进、朱红细线、少装饰 | 散文、随笔、观点、书评 |
| 学术理工风 | 宋体标题、深蓝点缀、左侧竖线、浅蓝引用框 | 理工科、技术分享、实验记录、教程 |

喜茶风的视觉规则整理自 24 篇喜茶官方公众号推文（2021–2026）的排版分析，只借鉴版式规则，不使用任何官方图片或素材。

### 3. 自定义点缀色

通过 `--accent "#RRGGBB"` 替换整套风格的点缀色，适配不同主题。

### 4. 排版质量自动检查

`validate.py` 输出 7 项检查结果，命令行返回非零退出码，便于接入自动化流程。

### 5. 命令行一键运行

```bash
python skill/wechat-article-typesetter/scripts/typeset.py examples/sample-article.md \
  --style heytea --author "化工小张" --output examples/output/sample-heytea.html --validate
```

### 6. Agent Skill 集成

把 `skill/wechat-article-typesetter/` 放入支持 Agent Skills 的目录后，AI 在用户提到"公众号排版""推文排版"等场景时自动加载 `SKILL.md`，并按其中步骤调用脚本。

## 六、项目创新点

### 与普通人工操作相比

- 人工排版需要逐项设置字体、字号、颜色、间距；本项目把这些规则固化在 JSON 配置里，一次配置、反复使用。
- 人工容易漏掉对比度、行高等细节；本项目用算法自动检查并给出具体数值。
- 人工每次排版结果不一致；本项目同样输入必然得到同样输出。

### 与简单 AI 对话相比

- 普通 AI 对话生成 HTML 依赖模型临场发挥，可能带外部 CSS、class、脚本，粘贴进公众号后失效；本项目生成的全部是内联样式，且校验器会拦截外链和禁用标签。
- 普通 AI 对话难以保证 677px 容器、16px 正文、行高 ≥1.6 等硬指标；本项目把它们写成可执行的检查项。
- 本项目把"何时用、怎么用"放进 Skill，把"实际执行"放进脚本，职责分离，结果可测试。

### 真实存在的技术或流程特点

1. **公众号粘贴场景优先**：不使用 `<style>`、class、外部字体和 JS，全部内联样式。
2. **可量化的排版检查**：按 WCAG 公式计算文字与背景的对比度，普通文字要求 ≥4.5:1，大字要求 ≥3:1。
3. **零第三方依赖**：只用 Python 标准库，任何安装 Python 3.9+ 的电脑都能运行。
4. **双层交付**：Agent Skill 负责流程约束，Python CLI 负责确定性执行，二者可分别使用。

不夸大：本项目不是设计软件，不生成图片、插画、动画，也不替代人工审美判断；它解决的是"稳定、快速、可复制地完成基础排版"。

## 九、已知限制

1. 只排版用户提供的文字，不代写、不改写正文。
2. 不支持图片、图床、封面图，图片需在公众号编辑器中手动插入。
3. 不支持表格、SVG、动画和点击交互。
4. 字体依赖读者设备，不同系统渲染略有差异。
5. 生成的 HTML 是静态近似，不等同于专业设计软件产出。
6. 未在真实公众号后台完成最终粘贴验证（见第七节说明）。
